Guardian Platform Architecture

O Guardian foi projetado para solucionar a principal deficiência dos agentes de observabilidade tradicionais: o consumo fixo excessivo de recursos e a complexidade de configuração. Através de Targets Cirúrgicos gerenciados por goroutines de alta performance, o motor supervisiona apenas os namespaces ou containers que a sua operação realmente precisa acompanhar.

Componente Kubernetes Engine Docker Engine
Descoberta de Contexto Leitura de ~/.kube/config com highlight de contexto ativo Conexão via Unix Socket (/var/run/docker.sock) ou TCP remoto
Granularidade do Target Namespace (ex: producao, billing) Stack Compose / Containers Individuais
Mecanismo de Escuta client-go Informers & Pod Lifecycle Watcher Docker Engine Events Stream (die, oom)
Captura de Falhas CrashLoopBackOff, OOMKilled, ImagePullBackOff, Exit != 0 Exit Code != 0, OOMKilled (Exit 137), Healthcheck Fail
Automação de Resposta Chamado Jira com kubectl logs --previous Chamado Jira com docker logs --tail=50

100% Extensível

Adicione novos provedores de nuvem (AWS ECS, Nomad, Proxmox) e integradores de mensageria (Slack, Discord, PagerDuty) implementando interfaces em Go.

Governança & Least Privilege

Requer apenas permissões de leitura (get, list, watch) no cluster K8s. Nenhum token com permissão de escrita ou destruição é necessário.
